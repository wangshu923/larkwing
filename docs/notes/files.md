## 文件授权圈(能碰的文件夹)

> 来源:分家前 AGENT.md「7.2 文件能力(PLAN §9「文件能力」)」L323–L329。

- **★文件授权圈(2026-07-30 落地;Mac 全绿 573+16 / clippy 触点零警 / vue-tsc / i18n 镜像双侧相等 / 预览验过三钮卡与设置卡 zh+en;真机 watch 见 PLAN)**:只有明确允许的文件夹,模型才能读写;程序数据目录免授权。
  - **闸的是模型的手脚,不是程序自己**:只拦「模型经工具入参指定的路径」(fs 家族 11 原语 + media_play 本地 / qr_decode·read_image 显式路径 / pdf_to_png 源+产物 / send_file / web_render 上传与下载落点 / web_download·media_download·torrent_download·ftp 落盘 dir / lyrics_fetch / desktop open 文件臂,共 17+ 接入点);程序内部读写(TTS/媒体缓存、日志、收件区——全在数据根下)不经工具层,零影响。
  - **三档 × 四动作**(§4.11 用户拍板,单源 `tools/guard.rs`):只读 read(看)/ 可存入 create(看 + 落新文件,不动已有)/ 完全访问 full(+修改+删除)。动作分类:读 / 新建 / 修改(覆盖·编辑·移走,fs_move 源按修改判)/ 删除;write/append 按目标存在与否分新建/修改。**内置区**:数据根 + 系统临时目录恒 full 免问;**下载 + 桌面 = 出厂基线「可存入」**(升 full 落一条表记录、降档删记录回落基线,设置页不给内置行「只读」)。
  - **匹配与合并**:授权即覆盖整棵子树(按路径**组件**前缀比,`D:\Movies2` 蹭不上 `D:\Movies`;Win/mac 大小写不敏感;规范化 = expand_home → canonicalize 存在的最深祖先(产出过 `datadir::simplify` 防 §8.1 verbatim 毒)→ 词法归一 `..`);入表自动合并被覆盖、档位 ≤ 新条目的子孙记录,**档位更高的子条目保留(绝不静默降级)**。表 = settings app 级 `fs.scopes`(JSON;专用命令 `fs_scopes_list/fs_scope_set/fs_scope_remove` 收口,不进 `APP_SETTING_KEYS`,llm.model_overrides 同款)。
  - **撞圈 = 确认卡三态**(复用 §7.8 Confirmer,四通道白拿):「**一直允许**」按所需最低档入表(读→read、新建→create、改/删→full);「**仅这次**」= 本回合内该目录临时放行(`ToolCtx::grants`,回合结束即丢;**2026-08-18 起「本回合」延伸到它派生的 delegate 子回合**——共享同一份缓存,含转后台续跑的那段,不二次弹卡);拒/超时 = 错误观察喂模型(话术带「如实说、别换路径绕」),**拒过的目录本回合不再弹**(拒 read 连 full 也不问;拒 full 不挡后续 read 请求)。同批多目录并一张卡;批量转后台的(下载/BT)**授权前置到 spawn 前**,job 里无交互点。**渠道文字回话 / 语音口头「允许」恒按仅这次**——永久授权是改机器配置,只留给有 UI 的地方(桌面 HUD 卡 / 悬浮窗三钮)。Confirmer 应答随之三态化(`ConfirmReply`;审计 decision 多一档 `allowed_always`,足迹页能看出「以后不再问」)。
  - **UI**:设置·系统「能碰的文件夹」卡(内置三行〔程序数据说明行 / 下载 / 桌面〕+ 用户条目三档可调可删 + 添加走 `pick_data_folder` 原生选择器,新加默认只读);审计走 confirms 域白拿。**工具描述刻意零改**(拒绝话术已自解释,省 token 且前缀缓存不失效——比方案预估更省的落法);**不做需知自动迁移**(老用户首次撞卡点一下「一直允许」即完成补票)。
  - **接线纪律:新收路径的工具一律在拿到路径后、动手前过 `guard::ensure(ctx, Access, paths)`**(expand_home 同款;fs_undo 也过——先读记录再 ensure 再执行)。**明确不做**:单文件授权(目录粒度)/ 通配符规则 / 审批等级与总开关(§7.8 同口径:能关的闸出事就是产品事故)。

## 压缩包原语 fs_unzip / fs_zip

> 来源:分家前 AGENT.md「7.2 文件能力(PLAN §9「文件能力」)」L332。

- **压缩包原语 `fs_unzip` / `fs_zip`(2026-08-12 落地;用户拍板三件全上:rar/7z 一期就带、密码支持、打包半边也要)**:解压 zip/rar/7z + 打包 zip(为「一批文件 → send_file」;只产 zip——RAR 许可只准解不准造)。**按文件内容认格式**(魔数,0.2.27「名字是 mp4 内容不是」同教训,假后缀照认;分卷 rar 给第一卷,库自动跟卷)。**解压恒落全新文件夹**(`base/<包名>`,dedupe 加序号 = 资源管理器「解压到 <名>\」口径)→ 永不覆盖天然成立、**不进 fsops**(清理 = 整夹 fs_trash;包内重名/非法字符清洗撞名的条目落盘时 dedupe_path 加序号)。边界闸:条目路径逐组件重组拒 `..`/绝对形(zip-slip)+ 组件过 sanitize_filename;zip 老编码文件名非 UTF-8 按 **GB18030 回退解码**(国内 GBK 常态,乱码 = 白做);解开总量 >50GB 拒(`ARCHIVE_MAX_BYTES` 与 torrent 同「影视量级」口径,不另造第二个数);**带密码没给密码在盘点期就如实要**(preflight 先盘条数/总量/加密,不做一半才发现),password 只填用户给的。执行 = `media/archive.rs` 走 edit.rs 同款「回合内 30s → 转 bgtasks」(`IN_TURN_WAIT` 单源上移 pub(super);〔此刻〕/进度 i/n/task_cancel/收尾唤回合/看门狗全白拿;取消粒度 = 条目之间「正在写的这个写完就停」;**半成品收拾在阻塞闭包里兜**——失败/取消整删新文件夹/临时件,看门狗把守望任务掀了由 `CancelOnDrop` 递旗给阻塞线程自清)。引擎 = 顶层 `archive.rs` 纯同步可测:zip = zip crate(补 `aes-crypto` 特性)、7z = `sevenz-rust2` 0.7(**被 rust-version=1.77.2 钉版**——resolver 尊重 MSRV,新版要 1.85+;`aes256` 特性;bzip2 压缩形没开,撞上如实报)、rar = `unrar` 官方源码绑定(vendored C++/cc 编译;许可只准解压,恰好)。授权圈:包 = read、新文件夹/成品 = create(前置);出厂技能三条(BT下载/网页上办事/整理文件)补「是压缩包先解开」接线。**已知边界**:rar 路**无本机单测夹具**(mac 无 rar 打包工具;引擎与 7z 同构、错误码已映射 MissingPassword/BadPassword/BadData)= 真 rar 包 + 密码 rar 归真机验;unrar 的 C++ 在 Windows MSVC(CI release)首次编译也是 watch。Mac 全绿(新增 13 测:引擎 8 + 工具 3 e2e + 微信侧 2)。

## 磁盘占用原语 fs_usage

> 来源:分家前 AGENT.md「7.2 文件能力(PLAN §9「文件能力」)」L333。

- **磁盘占用原语 `fs_usage`(2026-08-13 落地;能力对账批用户圈选)**:只读直交原语,统计一棵目录树的占用——整树聚合,报「第一层子目录 TOP 15 + 全树最大文件 TOP 10 + 总量/文件数」(两个 TOP §4.11 用户拍板);「C 盘怎么满了」= 模型对着最大子目录反复下钻组合出来(§5,不造 cleanup 任务工具;清理动作走既有 fs_trash 可逆)。引擎 `usage.rs` 纯同步可测:不跟 symlink/junction(防环 + 防重复计数)、没权限的目录跳过**计数如实报**(绝不装算全了)、深度 64 backstop 计 denied;执行 `media/usage.rs` = archive 同款「回合内 30s → 转 bgtasks」(〔此刻〕/进度/task_cancel/收尾唤回合/看门狗全白拿)。**总数未知按 total=0 提交,顺手修了 bgtasks 显示端「total=0 不显分母」**(单源 `progress_frag`,四处渲染点;原先会显 0/0,清点型任务进度改靠 current 文案「已数到 N 个」;存量 total>0 任务显示零变化)。只读活无半成品,取消/drop 只递旗停扫省 IO(`CancelOnDrop` 可解除武装,交棒后台不误伤)。授权圈 read(扫 C:\ 就弹 C:\ 的读授权卡,机制本来的样子)。配套出厂技能「电脑清理」(§7.9)。Windows 真机 watch(PLAN):真大盘扫描时长 / 系统目录权限跳过计数 / junction 的 `is_symlink` 行为 / C:\ 读授权卡体感。

## 属性原语 fs_stat + fs_list/fs_find 捎改动日期

> 来源:分家前 AGENT.md「7.2 文件能力(PLAN §9「文件能力」)」L334。

- **属性原语 `fs_stat` + fs_list/fs_find 捎改动日期(2026-08-13·三批;「照片按拍摄时间归档」的时间半边——此前全家族连修改时间都不报)**:① `fs_stat` 只读批量看属性(paths ≤300 同 fs 批量纪律;结果顺序与传入一致、每文件一行只报 file_name 省 token):大小 + 修改/创建时间;照片带 EXIF 拍摄时间(「2024:01:15」形归一「2024-01-15 13:20」)/相机/分辨率(读头不解码;HEIC 解不出分辨率就省略、EXIF 半边照报);mp4/m4v/mov 带时长(`probe_local` 免 ffmpeg 白拿;mkv/mp3 刻意不报——不为一行属性拉子进程)。**独立成原语、不塞 fs_read_text 的原因**(2026-08-13 用户问「readfile 加参数读属性行不行」→ 讨论后拍板分开):内容读取天然单文件(offset 续读),属性读取天然整批(几百张照片一张一调 = 回合爆),塞一起是「内容收 path、属性收 paths」的双形 schema。依赖 +`kamadak-exif`(纯 Rust 零依赖);EXIF 单测 = exif Writer 手拼 APP1 JPEG 回读归一化。② fs_list 行改「名字 (大小 · 改动日期)」、fs_find 尾捎「(日期)」——「找我昨天下载的那个」直接可判。分工三句话进各自描述互相指路:fs_list/find = 扫一眼,fs_stat = 细看属性,fs_read_text = 读内容;整理文件技能补「按时间归类先 fs_stat」。真机 watch:真 iPhone HEIC / 微信导出照片的 EXIF 存活率、Windows created time 口径。

## 读类三原语一律「一页 + 报总数 + 给续读起点」

> 来源:分家前 AGENT.md「7.2 文件能力(PLAN §9「文件能力」)」L337。

- **读类三原语一律「一页 + 报总数 + 给续读起点」(2026-08-15;原先只有 fs_read_text 有 offset,list/find 截断了后面**永远**看不到,只能换更细的条件——真机撞上)**:`fs_list`(一页 200)/ `fs_find`(一页 50)/ `fs_read_text`(一页 4 万字)都收 `offset`,截断时把**总数**一并给出(用户提:模型据此才判得出该翻页还是该换更具体的条件),越界如实退回。两个连带约束:① **顺序必须稳定**才配分页 —— fs_list 本就 dirs/files 各自排序,fs_find **改成收齐后按路径排序**(read_dir 原始序不保证);② fs_find 为了报总数不能再「凑够一页就停」,改扫到 `FIND_SCAN_MAX=1000`(§4.11 待拍板的失控 backstop:深度上限 4 + 工具 30s 超时仍在)、扫满就如实说「可能还有,换更具体的模式」。**聚合型输出不套这个形**(`fs_usage` 的 TOP15/10 是聚合不是截断,全量对模型无用);批量写原语超额仍是**报错分批**不是分页。

## fs_find 返回文件夹 + 广度优先浅层先出

> 来源:分家前 AGENT.md「7.2 文件能力(PLAN §9「文件能力」)」L338。

- **fs_find 返回文件夹 + 广度优先浅层先出(2026-08-18;真机实锤:剧集库「米老鼠四季各几十集」第一页被第一季灌满,agent 误判只有两季)**:病根三环 = 只返回文件(季文件夹骨架根本不在结果里)+ 一页 50 + **显示顺序由收齐后的纯路径排序决定**(字典序 = 第一季全部先出;⚠️ 光换遍历显示不会变——sort 会抹掉遍历序,真正要换的是排序键)。修三处(单文件 `tools/fs.rs`):① 文件夹与文件**同一套匹配口径都算命中**、以 `/` 结尾(fs_list 同款标记),命中的文件夹照样往下钻(子项可能也命中);② 收集改**广度优先**——撞 `FIND_SCAN_MAX` 时浅层保证扫全(截掉的只是更深的),每层条目按名排序 → 截断集合确定(旧 DFS 撞上限时收进哪些取决于 read_dir 原始序,不保证);③ 排序键「路径」改「**(深度, 路径)**」浅的先出 = 骨架先看到,description 改口(文件夹以 / 结尾、想看里面接 fs_list)。深度可达层数刻意不变;上条「fs_find 改成收齐后按路径排序」的排序键半句由本条取代。**「截断时报命中分布」评估过不做**(用户拍板:只针对单 case、破坏原语单纯性,case 解不完——这正是 §5 不造任务形聚合的又一次兑现)。
