> 来源:分家前 AGENT.md「7.4 提醒 / jobs / web(PLAN §10)」L352。

- **web 三件套 = 搜索即抓取 / 读页 / 存盘(2026-07-10 由二件套扩)**:`web_search` 一次带回 top3 正文证据片段(修掉 robot「链接堆 + 串行 fetch」多轮往返);`web_fetch` 读正文 + PDF/二进制直链如实拦下指路「web_download 下载 → fs_read_text 读」(只认明确二进制 CT / %PDF 魔数,误拦比漏拦贵;web_search 正文富化撞 PDF 同闸静默降级只剩摘要——原先会把乱码当证据)。**表格转 markdown(2026-08-13)**:正文抽取遇 `<table>` 单独转 markdown 表(首行当表头〔野页面多半没规范 罐**——Bing 国内版首次请求必 302 去种 market cookie,没罐就在跳转链上打转;② **只有 UA、缺整套浏览器头**(Accept / Accept-Language / Upgrade-Insecure-Requests / Sec-Fetch-*);③ **全程在跑 HTTP/1.1**——reqwest 0.12 的 h2 在 `http2` feature 后面,而 `default-features=false` 手列时一直漏了它,**现代浏览器对 https 一律 h2,只说 h1.1 就是机器人特征**(同 cookie 同头,curl 走 h2 出 10 条、`--http1.1` 直接进验证页)。**坏法有三种,最阴的是第三种**:(a) 人机验证页(解析 0 条);(b) 重定向死循环;(c) **跳转链上 query 被弄丢,回一个「结构完整、内容却是别的」的结果页**——解析出一堆形似合法的命中原样喂给模型当证据(同期实锤:模型据此编造 .lrc 时间轴)。**顺带两个坑**:`count=10` 参数本身就是机器人特征(带上 0 跳进验证页、去掉 6 跳出 10 条,而条数本就是解析时 `.take(count)` 裁的,**别再加回来**);重定向上限放宽到 20(Bing 引导 6 跳起、偶尔追加 `mkt=` 冲破默认 10 跳)。**三源按实测「可靠度 × 快」排**(同机实测):搜狗 0.96s 零跳、国内直连稳、`data-url` 给真实直链 → Bing 索引最好但**冷启 6 跳引导 ≈26s**(热 3.8s)当不了第一源 → DDG 垫底(国内常不通,通时 ~1s);搜索单请求超时 30s(容得下 Bing 冷启),抓正文仍 15s。**合理性闸 `looks_relevant`** 拦 (c):查询抽「ASCII 单词 + 相邻双汉字」当信号(**单个汉字太弱刻意不收**——否则「周」字条目会被判成「周深…」的相关结果),一条命中都不沾就换下一个源;**刻意宽松**(误杀只是多退一个源,误放是把垃圾当证据)。**限流是常态、不是缺陷**:密集测试几分钟后搜狗/Bing 都会发验证码页(解析 0 条 → 自动换源),三源链的价值正在于此。选择器仍是代码不是数据,坏了改 `web.rs`;`web::tests::real_source_report`(#[ignore] 手动跑)= 「搜索又不对劲了」的第一件工具,逐源报「报错 / 0 条 / 有结果但没过闸」。web_render 6000 字截断刻意不动(操作用途、每步重新快照 offset 语义不稳)。

## FTP 下载(web_download 分支;死链判据 / GBK 边界 / REST 断点续传)

> 来源:分家前 AGENT.md「7.8 轻办公原语:二维码 / 下载 / PDF 转图 / 发手机(2026-07-10 落地;发票链是试金石不是任务工具)」L475–L481。

  - **「只有迅雷下得动的 ftp 链」= 那台服务器已经死了,不是协议有门禁(重要,别再被这说法绕进去)**:FTP 是开放标准(RFC 959),协议里**没有** User-Agent 这类东西给服务器识别客户端,任何客户端都能连。迅雷能下死链是因为它早把「URL → 文件哈希」记进索引、从自己的 P2SP 缓存给字节,**根本没碰那台 FTP**(V2EX/知乎社区共识,已查证)。我们没有缓存池 → **死链谁也变不出来**,活着的照常下。判据看错误:**连不上 = 服务器死了;连上但 550 = 文件名对不上**(见下条编码)。
