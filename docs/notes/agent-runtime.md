## 计划槽 plan_set = agent 会话内工作备忘

> 来源:分家前 AGENT.md「6.5 通用回合循环 / 工具运行时(PLAN §8)」L209。

## few-shot 纪律 + 示范内容泄漏三处数据源

> 来源:分家前 AGENT.md「6.5 通用回合循环 / 工具运行时(PLAN §8)」L214。

- **few-shot 纪律**:每场景 2–4 段、总预算 **≤800 token**、**至少一段反例**(不该调工具的对话);示例 id 用 `fs_*` 前缀与真实 id 隔开;加载时校验(引用工具 ⊆ 白名单、call/result 配对完整)。**任何 few-shot 都绝不嵌「具体、可复用的事实」**(不只 remember 示范——闲聊/建议类示范同样会泄漏):有名有姓有属性的虚构人物会被当真人(「朵朵」bug);**带属性的具名清单**(地点/资源)会被模型当用户真事抄进 remember(2026-06-18 实锤:建议示范里「湿地公园(放风筝、喂鸭子)、科技馆、采摘园」被原样记成「用户周末常去的三个地方」)。对策:示范内容要么是一次性/自我纠正的事实(不吃香菜),要么是**泛指、无可复用属性**的方向(「户外走走/室内逛逛」),绝不出现结构化的「具名+属性」清单。**统一判据(2026-06-18 再实锤,扩到结果行)**:few-shot 只教**工具形状 + 说话风格**,绝不携带任何模型会误当「用户真事」或「自己已知事实」的具体内容。**头号泄漏口 = `role:tool` 结果行**——模型分不清示范结果和真实结果、且把结果当真相:实锤是默认场景示范里「放流浪地球2 → fs_find 本地没找到 → 转 B站蓝光修复版」,模型把「流浪地球2 本地没有」当成既知事实、**跳过 fs_find 直奔 media_search**(真用户本地明明有)。所以 ① 示范里的真实片名/歌名/歌手/城市一律换**编造占位**(用户永不会点的名字,如「星海漫游」)或**泛指类别**(「儿歌」),让即便被记住也与真实请求不碰撞;② 真实落空/命中类结果不绑定真实作品;③ LAWS「出厂示范」隔离条**立原则、不举例**(教学归 few-shot,§7.3「法条只立法条」——别把「本地没找到某片就跳过」这种 worked-example 塞进法条,那本身就是「往提示词塞具体内容」的毛病,且 few-shot 已在演示 fs_find 先行):法条只说「示范里工具查到的结果全是编的、不是你自己已知的事实,该查证的仍要现查现问」。回归守卫:`eval/scenarios.rs::media-local-first`(登记电影目录后点播,断言先 `fs_find` 再 `media_search`)。`scenes.rs::validate` 只管结构(配对/前缀/白名单),抓不了内容泄漏 → 这类靠本规则 + eval 守。**(2026-07-21 实锤扩面)泄漏口不只 few-shot——工具描述里的示例内容同样被抄**:briefing_write 的 content 参数示例『如「电影在 \\\\nas\\film 和 D:\\Movies;…」』被模型当「已有目录」合并进真实需知——用户只说了「~/Downloads 有电影」、briefing_lookup 明确返回无记录,它仍写入「电影在 D:\\Movies 和 ~/Downloads」并对用户转述(reasoning 里全程没提 D:\\Movies = 无意识照抄)。规则:**工具描述(= 提示词)里的示例只教参数形状/格式,绝不带具体可复用内容**——真实感路径/地名/片名一律去掉或换明显占位(D:\\某文件夹、\\\\nas\\共享名);**写入类工具(briefing/remember/todo)的 content 示例风险最高**(写入常带「合并旧内容」语义,示例内容最易被当旧事实端进来),宁可无示例只描述形状 + 明写「只写用户真实说过的信息」。同批已清:briefing_write content 示例、fs_list/fs_find 的 D:\\Movies/佩奇、desktop open 的 D:\\照片(remember/todo 的示例暂判低风险留观——无合并语义;若真模型再实锤照此清)。**同日二审(描述修完、重编重测仍复现)→ 真主源 = 场景 few-shot 本身**:companion.json 的 briefing **合并示范**(fs_b2『电影在 D:\\Movies;音乐在 D:\\Music』)与真实泄漏逐字同构(分号合并、D:\\Movies 打头);新会话 + 空需知 + 已修描述下照样复现,坐实合并语义的示范内容会被当「已有旧内容」端进真实写入。修 = ① 示范路径全换**自标示例的占位**(D:\\示例片库 / D:\\示例曲库 ## 落库 payload + 同轮多段合并渲染 + 想了想时间序两级展开

> 来源:分家前 AGENT.md「6.5 通用回合循环 / 工具运行时(PLAN §8)」L215。

- **落库**:messages 加 nullable `payload` TEXT(assistant 行存 tool_calls + 该轮 reasoning;`role='tool'` 行存 call_id/name/status);UI 渲染过滤 tool 行。**同轮多段合并渲染(2026-07-10 用户拍板)**:带工具的一轮"说话→调工具→再说话"落成多条 assistant 行(工具配对/逐段轨迹是承重结构,**库不动**),聊天流由 `MainLayout::streamGroups` 把相邻 wang 段**分组进一个气泡**——段间只留段落间距,复制/朗读/读数收组级(整组文本),逐段「想了想」仍跟各自的段(**2026-08-15 起摆在该段正文之前 + 展开层改成时间序两级**:① 位置——`conversation_trace` 的封口语义 = trace 挂到它**后面**那条可见回复上 → 药丸里装的**全是这段话说出口之前**发生的事〔CoT 是先想的、工具是上一轮回填的〕,原先摆正文下方读起来成了「先说后想」,流式时更刺眼——thinking 先到、delta 后到,药丸先冒出来文字却在它上方长;② **展开层 = 一条按时间排的队列,不是两个桶**——`TurnTrace` 由 `{steps, reasoning}` 改成 `items: Vec<TraceItem>`(`Thinking{text}` / `Tool(TraceStep)`,serde 内部 tag),`conversation_trace` 单队列组装(一条 assistant 行 = 一轮,轮内恒「先想 → 再调工具」,照到达序入队即得真实时间线;live 侧 thinking 增量累进**当前**那条思考条目、中间隔了工具就另起一条,与回放同构),修「思考块全堆在最下面、上面一排工具」;③ **两级展开**——展开层每条只一行人话(工具 = 各自 `tool.*` 人格化动词去掉进行时省略号、思考 = 「思考」),**再点一下**才露细节(工具名/入参/结果、或 CoT 原文);**在飞也要有东西可看(2026-08-16 修,真机实锤:批量回合一跑几分钟,这期间展开全是光秃秃的动词、点都点不开)** —— `TurnEvent::ToolUse` 由 `{label, state}` 扩成带 `id`(call_id 配对,同轮并发同名调用也认得准)+ `name`(原始工具名)+ `args`(Started 带)+ `result`/`status`(Finished 带),两者**按字符截断**(`LIVE_ARGS_MAX=400` / `LIVE_RESULT_MAX=300`,单源 turn.rs;不截 = 把 fs_write_text 正文、web_fetch 整页正文再走一遍 IPC)。原「入参/结果故意不入流」半边作废,收尾 hydrate 仍用落库全量版整条覆盖(**在飞看个大概,跑完看全**)。仍无细节可看的条目(如 `now`:无参、结果未回)**不给箭头也点不开**,免得点开一片空。折叠层「N 步」只数工具条目,回执小票/建议气泡同口径〔`useChat::traceTools` 单源〕),**回执小票**(见 §7.4 ②)收组级、排气泡末尾;user 恒单条一组、event 行是系统线、跨天分隔断组。修「一轮被切成一串小气泡」观感;皮肤零特调(组是一个 .bubble,切角/圆角天然完整)。

- **媒体附件:图当轮、文档文字进 history(2026-06-29 用户拍板,收窄原「图+文档都当轮」规则)**:**图片**仍**当轮注入、不落库**(后续回合看不到上轮的图、要再发)——因为 vision 对旧图反复计费。**（2026-07-04 补:图 bytes 另落文件供 UI 回看)**——「不落库/不喂 LLM」只约束 DB 与模型输入;为了 UI 体验,图片 bytes 写到 `<media>/attachments/<内容hash>.<ext>`(§6.2 blob 走文件),`AttachmentRef.file` 记相对名,重开会话经 `attachment_url` 命令→relay `/f/` 拉回缩略图。LLM 仍永不重见旧图(build_context 不碰这些文件)。**(2026-07-11 补:历史带图行加装配标记「〔附了N张图〕」)**——图不回放让模型对「刚发过图」零感知,下一轮说「把它下载/认一下」就路由不到 qr_decode 等吃「最近一批图」缺省的工具(微信真机实锤);同〔语音〕:装配现加不落库、同输入同翻译,前缀缓存零损伤(`context.rs` 读 `UserMeta.attachments` 数 image)。但**文档「文字」并进落库的 user 消息内容 → 进 history**:多轮追问文档还在,且文档落**可缓存前缀**(首轮全价、后续 cache-read,§4.8),治掉「问完文档接着问就丢了」。落点 = `engine/mod.rs::send_message` 把 `process_attachments` 抽的 `doc_text` 拼进 `append_message_full` 的内容(图仍走当轮 `parts`);inject 路径 `turn.rs::apply_injection` 同步(落 `llm_content` 含文档、UI 事件仍用 `display` 原文)。代价 = DB 存这份文字、会话记录变大(用户主动塞文档才付,可接受)。**与本条同批落地的上下文处理重构见下条。**

## 上下文处理 = 单一字数预算 + 整块锚定;计价感知;模型高级设置 override

> 来源:分家前 AGENT.md「9. 边界 / 暂不做 🔒(别擅自做)」L579–L581。

- **上下文处理 = 单一字数预算(model-aware)+ 整块锚定,无条数窗口(2026-06-29 落地)**:原「`WINDOW_MAX=48` 条数窗口 + 48K 字安全阀」两套机制**合并成一个** `engine/context.rs::windowed_start`(字数预算裁 + `WINDOW_CHUNK` 绝对整块锚定保前缀缓存 + 边界吸附防拆 tool 配对)。预算由 `tail_budget_chars(catalog::ctx_window_of(model))` 算:**未知窗口回落 `DEFAULT_TAIL_BUDGET_CHARS=48_000`(零行为变化);大窗口在 [默认, `MAX_TAIL_BUDGET_CHARS=300_000`] 间放大(装文档);小窗口(本地)缩到默认以下(防溢出)**——`= min(MAX, 窗口token/TAIL_RESERVE_DEN)`,CJK 最坏 1 token/字故 token 数当字数上界=安全。`catalog::ModelInfo` 加 `ctx_window_tokens`(数据,2026-06 采集,全 200K–1M)。**判据 = 预算只缩或在 [默认,MAX] 间放大、绝不无界增长;常态(字数≤预算)起点=0、缓存零损伤**。caller 按 `HISTORY_PAGE_MAX=800` 条做 I/O 分页(非语义窗口)、传 `page_base` 给 windowed_start 做绝对锚定。**✅ 2026-06-30 Windows 真机/真量验过**:大窗口模型真装大文档、多轮缓存命中、小窗口模型不溢出、长会话预算迟滞不 creep。阈值单源 `context.rs` 顶部,§13.7「只能真用才能调」。
