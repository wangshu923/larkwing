## 交互听音段前滚 1.0s(唤醒后报数字丢头)

> 来源:分家前 AGENT.md「7.5 语音(PLAN §11)」L361。

- **★交互听音段前滚 1.0s = 治「唤醒后报数字丢头」(2026-08-31 用户拍板落地;真机实锤「123456789 → 大多数时候 3456789、偶尔 34567」)**:根因在 **sherpa silero VAD 的触发语义 × 断续开头韵律**(上游 v1.13.2 源码核对)——`IsSpeech` 要求**连续** `min_speech_duration=0.5s` 高于阈值才触发,且触发前**任何一个 32ms 窗掉下阈值就把已积累的人声清零重计**(`temp_start_=0`);报数字式开头「一…二…」每个音节凑不满 0.5s、被反复清零,VAD 从「三四五…」连起来那段才触发,而段起点只回退 `min_speech+2×window`(≈ 连续段起点前 64ms)→ **「一二」结构性落在段外,ASR 根本没听到**(正常整句连续说话一次凑满 0.5s、回退带回全部,所以平时聊天不暴露)。修三件,单源 `voice/mod.rs`:① `collect_utterance` 自缓冲喂入样本 + 出段按 `seg.start()` 回切 **`UTTER_PREROLL_S=1.0s`** 前滚(§4.11 用户拍板;`pad_utterance` 纯函数,越界/复用未 reset 的 vad = 回落裸段绝不切错)——唤醒指令/听写/跟进窗/口头确认四条路全治;**录制类采集(标定 RAW/克隆参考音/声纹注册)传 0 忠实原声**(前滚底噪会被克隆学走/稀释声纹);`CaptureOut::Utterance` 带 `speech_from`,**反幻觉闸与声纹识别按裸段算**、只有 ASR 吃整段;② **cpal 采集通道 64→512 帧**(~5s):唤醒确认层 ASR 同步阻塞期间「录音不断」靠通道缓冲,原 64×~10ms 只兜 0.6s,FireRed 档转写更慢时溢出丢新帧 = 抢话头几个字真没录上(browser 推流管 100ms/帧×64=6.4s 本就够,不动);③ 尾部偶发丢「89」= 数字串中途停顿超 hangover → 首段即定稿、后续落 AwaitTurn 丢帧——**机制不动**(所有语音助手共有的端点检测取舍,patience 档可调 relaxed;主修落地后不需要刻意慢念)。真机验收:唤醒后正常节奏报「123456789」头尾不丢 + 听写同验 + 声纹认人不回退(watch 见 PLAN)。

## 参考音先洗干净再入库:归一不硬削 + GTCRN 去噪 + 录入体检

> 来源:分家前 AGENT.md「7.5 语音(PLAN §11)」L363–L368。

- **★参考音必须先洗干净再入库:归一不许硬削 + GTCRN 神经去噪 + 录入体检(2026-08-21 用户拍板;真机「克隆音色播放莎莎声很严重」追因落地)**:零样本克隆把**录音条件当音色一起学走** —— 实测参考音底噪 −49dB ⇒ 输出底噪 −48~−50dB(一比一跟随,与 edge 云音色的数字级纯静音对比刺耳),安静间隙就是沙沙。故治法在**参考音**(一次性、离线、录入时做),不在输出侧(每次合成都要跑,还治不了模型照脏参考幻觉出的伪影)。三件:
  - ① **`peak_normalize` 硬削波 = 真 bug,已修**:它按 **99.5 分位**推到 −3dBFS,而语音真峰约在 p99.5 的 **1.8 倍**上 → 顶部那 0.5% 冲过满幅、被 `clamp` **切平**成削波失真(三重铁证:存盘参考音真峰恰 1.0000 / 30 个平顶样本 / p99.5 正落在目标 0.708;老参考没削只因它走的是**导入**路不过归一)。**且录得越轻增益越大、削得越狠** —— 所以「调低输入增益」这类建议是反的。修 = 增益取 `min(响度目标/p99.5, 0.99/真峰)`,**响度目标让位于不失真**,clamp 此后恒不触发(留作纵深);「只增不减」语义不变(源头已削的原样不动、不雪上加霜)。三条测试钉着(不许贴满幅 / 偏轻的仍要抬起来 / 够响的不动)。
  - ② **去噪 = GTCRN 神经模型,推理期零旋钮**(`voice/denoise.rs`;sherpa-onnx 同一原生依赖 §7.5「推理统一」+ 模型 0.5MB 用时下载 §6.9,`DENOISE_GTCRN` 钉死 sha256)。**「换个环境要不要重调参数」是选型的硬判据**:谱减法(ffmpeg `afftdn` 那类)要按环境手调 nr/nf、且在**音节尾音**处留「音乐噪声」伪影(用户耳测实锤「尾音、某些字结束的时候刺耳」)→ 实验后否决,绝不进产品;GTCRN 见过各种环境/信噪比,用时只有「音频进、人声出」,换会议室/客厅/厨房同一套零配置。实测:−49dB → −60dB(8 秒音频 158ms),用户耳测「外放听不出」。**尽力件**:模型下不来/加载失败一律不挡录入,体检里 `denoised:false` 如实告知(§3.5)。现场录音与导入音频**两条路一视同仁**都洗(手机录的、微信语音导进来的同样带底噪)。
  - ③ **录入体检 = 绝对量测量 + 一条可执行建议**(不是闸,照旧能保存):削波占比在**归一前**量(归一后峰值恒在目标附近、量不出输入侧),底噪量**去噪后**那份(= 克隆真正会学到的);结论优先级 削波 > 底噪 > 没能去噪,**一次只报一条**(§3 收敛,给一个明确动作不堆诊断)。阈值 §4.11 用户拍板、单源 `denoise.rs`:`NOISE_FLOOR_MAX_DB = −55`(落在实测「明显有莎莎」的 −49 与用户认可的 −60 之间;更严会让普通客厅反复被要求重录)· `CLIP_MAX_RATIO = 1e−4`(8 秒 16k 里约 13 个满幅样本)。core 只过 issue **key**,文案在前端字典(§6.6)。
  - **配套修 `delete_clone` 的 speaker 悬空(真机实锤)**:删克隆只删记录+文件、不回落 `voice.speaker` → 设置悬空,之后每次合成都报「音色不存在」,而用户在设置页只看到「没选中音色」、无从自救。修 = 逐用户清指着它的那条(家人各选各的,只动指着这条的);空值 = 回落默认。
  - **诊断方法论(可复用)**:「莎莎声」这类听感问题**先量再猜** —— `ffmpeg astats` 的噪声地板/峰值/平顶因子 + 自写百分位脚本,把「参考音 vs 输出 vs 云端对照」摆成一张表,因果一眼看出(地板一比一跟随);两段自然样本(新旧参考各一)比任何推理都硬。探针例子留作 fixture:`larkwing-core/examples/denoise_probe.rs`(吃 gtcrn onnx + wav,出去噪版 + 耗时)。

## 克隆音色输出归一响度 −16 LUFS + CLONE_RENDER_VERSION

> 来源:分家前 AGENT.md「7.5 语音(PLAN §11)」L369。

- **★克隆音色输出必须自己归一响度(2026-07-27 用户拍板 −16 LUFS 档;真机「BT 声音特别小」实锤)**:**ZipVoice 的输出响度照抄参考音的响度** —— 它(承 F5-TTS)把参考音按 `target_rms` 归一后喂模型、合成完再按同一比例缩回去,所以 `zipvoice_config` 里的 `target_rms` 是**条件化旋钮不是音量旋钮**,调它没用;参考音录得轻 ⇒ 这把嗓子永远轻。实锤数据(用户自己的 TTS 缓存,输出 RMS 与参考 RMS 一对一跟随):参考 0.154 → 输出 0.131~0.148;换 3.35s 短参考(0.0887,当初为降延迟)→ 输出全掉到 0.078~0.105 = −20 LUFS,语音可懂带(300Hz–3kHz)比云端音色还低 2.3 dB;BT 是低沉男声、能量压低频,笔记本喇叭砍掉低频后就是「特别小」。**参考音侧救不了**(峰值只剩 3 dB 余量,推高参考还动音色条件化)→ 治法在输出侧:`tts.rs::normalize_loudness`(门限 RMS 定增益 +12/−6 dB 封顶 → 5ms 前视限幅、瞬时 attack 指数 release,**不是硬 clip**;纯 Rust 守「ffmpeg 不进 TTS 链路」),常量单源在 `tts.rs`(§4.11:目标 −16 LUFS 是用户拍的,改档回来问)。**只归一克隆音色**——云端音色自带母带(用户拍板不动)。两条播放路一起覆盖:归一在 `ZipVoiceTts::synthesize` 里,应答音银行走的也是同一个 `tts_to_file` → WebView relay 与 cpal 直出都吃到。**配套 `CLONE_RENDER_VERSION` 掺进克隆的 cache_key**:响度常量变了旧缓存(含开机预合成的应答音)必须失效,否则改完参数还照播老响度 —— **改任一响度常量 = 该版本号 +1**;只掺克隆,免连带作废 edge 缓存(要重新联网合成)。标定夹具 = `#[ignore] loudness_real_calibration`(吃真 wav,改常量重跑;标定值落 −16.0~−16.5 LUFS、峰值 ≤ −0.1 dBFS)。
